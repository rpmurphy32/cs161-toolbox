Sorting & Selection · MT1
Selection sort Each pass scans the unsorted suffix for its minimum and swaps it to the front. O(n²) always ~n²/2 comparisons even on sorted input, but only Θ(n) swaps (the sheet's code swaps once per pass, even with itself) - the sort to pick when writes are expensive.
Insertion sort Grow a sorted prefix one key at a time, shifting larger elements right. O(n) best
O(n²) avg & worst		 Running time ≈ n + #inversions, so nearly-sorted input is O(n) - the case where it beats merge sort.
Merge sort Divide and conquer: sort each half, then merge the two sorted halves. O(n log n) always
+ O(n) space		 Not in place - needs a scratch array. Analyze with the recursion tree (course only requires n a power of 2).
Quicksort Partition around a random pivot so smaller items land left and larger land right, then recurse on both sides. O(n log n) expected
O(n²) worst		 Random pivot ⇒ expected O(n log n) on every input - expected worst-case: the randomness is in the algorithm, not the input. Lecture partition = the two-pointer scheme.
Quickselect Find the rank-k element: partition like quicksort, but recurse only into the side containing rank k. O(n) expected
O(n²) worst		 One-sided recursion is exactly why it's expected linear instead of n log n.
Binary heap Complete binary tree where every node ≥ its children (max-heap); backs priority queues. insert/delete O(log n)
find-max O(1)		 Array encoding: children of x at 2x+1, 2x+2; parent at ⌊(x−1)/2⌋. Restore with swim (up) / sink (down).
Heapsort Heapify the array, then repeatedly delete the max into the freed tail slot. O(n log n)
heapify O(n)		 Bottom-up heapify is O(n), not O(n log n) - the deep levels have almost no nodes below them. In place.
Comparison-sort lower bound Theorem: no comparison-based sort beats n log n in the worst case (decision-tree argument). Ω(n log n) It says SOME input is slow, not every input - best-case sequences can still be fast. Also rules out too-fast comparison-based data structures.
Search Structures · MT2
BST (plain) Search / insert / delete by walking left or right on the ordering property. O(log n) avg
O(n) worst		 Random insertion order gives O(log n) height, but sorted insertions build a linked list. Two-children delete: swap with the in-order successor.
AVL tree BST where every node's subtree heights differ by at most 1, fixed by rotations on insert. O(log n) worst At most one single (Case 1, the worksheet's "Zig") or double (Case 2, "Zig-Zag") rebalance per insert.
2-3 tree Perfectly balanced tree of 2-nodes and 3-nodes; inserts fatten a leaf and split 4-nodes upward. O(log n) worst All leaves at the same depth - the tree grows at the root, not the leaves. A red-black tree is a binary encoding of a 2-3 tree.
Splay tree Self-adjusting BST: every access splays the node to the root via zig / zig-zig / zig-zag. O(log n) amortized
O(n) single op		 The bound is amortized - one operation can cost Θ(n). Splay on every access, including unsuccessful searches; skipping those breaks the bound.
Hash table (chaining) hash(key) picks a bucket; each bucket is a linked list of its items. O(1) expected
O(n) worst		 Two adversary models: operations chosen before a random hash fn ⇒ expected O(1); an adversary who knows the hash fn can force one bucket ⇒ O(n) per op. Totals = #ops × per-op cost.
Dynamic array Push (append at the end) into spare capacity; when full, allocate double and copy everything over. O(1) amortized push
O(n) single push		 Doubling makes n pushes O(n) total (the course's 'direct' method, or the potential method); growing by 1 each time is Θ(n²).
Graphs · Final
visit Reach everything reachable from one start node; the recursive core of DFS. Records preorder (on entry) and postorder (on finish). O(n + m) Without the visited check it loops forever on cycles / blows up on diamonds.
BFS Shortest paths when every edge counts as 1 (unweighted). Explores layer by layer. O(n + m) It's Dijkstra with all weights 1: FIFO queue replaces the min-heap. A node's dist is final the moment it's enqueued.
DFS (all nodes) Full traversal: call visit from every still-unvisited node. Pre/postorder power cycle detection and topological sort. O(n + m) Reverse postorder of a DAG is a valid topological order.
Topological sort Order a DAG so every edge points earlier → later (ready-list method: repeatedly take a node with no remaining in-edges). O(n + m) Only exists for DAGs - if the ready list empties early, the leftover nodes contain a cycle.
Dijkstra Single-source shortest paths with non-negative weights. Pop the smallest-dist unvisited node (finalizing it), relax its out-edges. O((n + m) log n)
with a min-heap		 Negative edges break it - it finalizes nodes permanently. Only write final dist/pred values in an execution table.
Bellman-Ford Single-source shortest paths, negative edges allowed. Relax every edge, pass after pass, until nothing changes. O(n · m) worst
O(n + m) best (early stop)		 Stops early once a pass changes nothing; a good edge order can converge in very few passes, the worst order needs ~n. Needs no negative cycles - if pass n still changes something, the graph has one.
Prim Minimum spanning tree: grow one tree from any start node, always adding the lightest edge leaving the reached set. O(m log n) The heap holds stale edges (both endpoints already reached) - that's what continue throws away.
Kruskal Minimum spanning tree: scan all edges lightest-first, add an edge iff its endpoints are in different components (union-find). O(m log n) Sorting dominates; union-find ops are amortized far below O(log n) each. Skipped edge = its endpoints already connected.
Tarjan Strongly connected components of a directed graph in one DFS pass, using number/low and a stack. O(n + m) node.low == node.number ⇒ node roots a sink SCC: pop the stack down to it. Know how to run it, not prove it.

n = input size (elements, or nodes in a graph); m = number of edges.
